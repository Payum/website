# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository state

This is the website repo for the Payum project. It started as the [Nuxt UI starter template](https://github.com/nuxt-ui-templates/starter); the homepage is now the Payum landing page, built from the **"Payum payment processing website"** Claude Design project (`4866bfce-7b8e-4fde-8d8b-873aad8b3b31`, readable via the `DesignSync` tool). That design is the spec for the page — check it before changing layout, copy or type scale.

`app/components/AppLogo.vue` and `app/components/TemplateMenu.vue` are leftover starter artifacts: nothing imports them, and their content advertises Nuxt's own templates. Delete them rather than reusing them. `main` has no commits yet — the whole tree is untracked.

## Commands

```bash
pnpm install         # also runs `nuxt prepare` via postinstall
pnpm dev             # dev server on http://localhost:3000
pnpm build           # production build
pnpm preview         # serve the production build
pnpm lint            # eslint . (add --fix to autofix)
pnpm typecheck       # nuxt typecheck (vue-tsc)
```

`pnpm` is the package manager of record (`packageManager: pnpm@11.20.0`, and CI installs with pnpm). A stray `bun.lock` also exists alongside `pnpm-lock.yaml`; don't use it to drive installs.

There is no test framework configured. CI (`.github/workflows/ci.yml`, Node 22) runs only `lint` and `typecheck` on every push — those two commands are the full gate.

**`.nuxt/` is load-bearing for both gates.** `eslint.config.mjs` imports `./.nuxt/eslint.config.mjs` and `tsconfig.json` only references `./.nuxt/tsconfig.*.json`, all generated by `nuxt prepare`. After a fresh clone, a dependency change, or anything that clears `.nuxt/`, run `pnpm install` (or `npx nuxt prepare`) before lint/typecheck, or they fail with missing-file errors rather than real findings.

## Architecture

Nuxt 4 with `app/` as the source directory: `app/pages/` is file-based routing, `app/components/` is auto-imported by filename, and `app/app.vue` holds the shell (header/footer, `useHead`/`useSeoMeta` defaults) around `<NuxtPage />`. Nothing is registered manually — adding a file is the wiring.

Four modules in `nuxt.config.ts` define what's available: `@nuxt/ui` (all `U*` components), `@nuxt/fonts` (auto-resolves the font families named in CSS, including Tailwind's `--font-*` theme variables — no manual `<link>` tags), `@nuxtjs/color-mode`, and `@nuxt/eslint` (generates the flat config).

The landing page is assembled in `app/pages/index.vue` from one component per design section (`app/components/Landing*.vue`), over three shared pieces: `SiteHeader`/`SiteFooter` (mounted in `app.vue`, so they wrap every page) and `CodeWindow`. Copy and lists live in `app/utils/landing.ts`, not in the templates, so text edits never touch markup.

`app/utils/php-highlight.ts` is a small regex tokenizer for the PHP samples, ported from the design. It runs during render — at prerender time for `/` — so no highlighter ships to the browser. It returns semantic token kinds mapped to `text-code-*` classes; add a color there, not a hex in a template.

### Dark only

The design system defines no light palette, so `nuxt.config.ts` pins `colorMode` to `dark` and the site offers no toggle. The theme tokens sit on `:root` rather than under `.dark`, which means the prerendered HTML is already correctly themed before the color-mode script runs — don't reintroduce `dark:` variants or a `.dark`-scoped palette without adding a real light theme.

### Styling: the design system is the source of truth

`app/assets/css/main.css` is the Tailwind-native port of the **Nocturne** design system with Payum's theme override (crimson accent `#cf2439` on a `#17161c` ground). There is no `tailwind.config.js` — Tailwind 4 is CSS-first. The file has four parts, in order:

1. `@theme static` — the `payum` and `ink` 50-950 ramps, grounds, `code-*` syntax colors, fonts, radii and the elevation scale. These generate the utilities (`bg-surface`, `text-payum-300`, `shadow-md`).
2. A `:root` block aliasing the design system's own token names (`--color-bg`, `--color-text`, `--space-*`) so the ported component layer reads from the variables the upstream system documents.
3. Nuxt UI's `--ui-*` surfaces, pointed at the Payum ground so a `U*` component dropped on a page lands in-palette. `app/app.config.ts` sets `primary: 'payum'` / `neutral: 'ink'` for the same reason.
4. `@layer base` / `@layer components` — the base type scale plus `.shell` (the page measure), `.btn*`, `.tag*` and the `.cell-rule-*` grid lines, ported from the system's `styles.css`.

**Take every color, radius, font and shadow from a token.** The design system lints against raw hex, raw px and unapproved fonts; a new value belongs in `@theme`, not inline in a component. Two specifics that are easy to get wrong: primary buttons are an accent *outline*, never a fill, and headings never go past weight 500 — hierarchy is size and space.

The page is built from plain semantic markup plus these utilities rather than Nuxt UI's `UPage*` components, because the sections are bespoke (the code window, the 1px-shadow grid rules, the stat band). Nuxt UI stays available and themed for future pages.

### Icons

Only two Iconify collections are bundled: `@iconify-json/lucide` (`i-lucide-*`) and `@iconify-json/simple-icons` (`i-simple-icons-*`). Names from other sets still render, but only by falling back to a runtime fetch from the Iconify API (`fallbackToApi` is on by default) — so they break offline and in prerendered output. Install the matching `@iconify-json/*` package instead of relying on that.

### Rendering

`routeRules` prerenders `/` only. Any new marketing page that should be static needs its own `routeRules` entry; otherwise it is server-rendered on demand.

Two build gotchas worth knowing:

- **Stale font cache.** `pnpm build` can die with a 404 on a `fonts.gstatic.com` woff2 when `node_modules/.cache/nuxt/fonts` holds a rotated Google Fonts URL (italic subsets rotate often). `nuxt.config.ts` scopes JetBrains Mono to `styles: ['normal']` — the site has no italic mono — which both avoids the broken italic fetch and trims the build. Clearing that cache directory also works.
- **`pnpm lint` vs `eslint .`** — `eslint .` walks `.remember/`, a local tooling directory that is git-ignored via its own nested `.gitignore`. ESLint only honors the *root* `.gitignore`, so a file in there can fail `pnpm lint` locally while CI (which never sees it) passes. Lint `app nuxt.config.ts` to check just this project's source.

## Code style

ESLint (via `@nuxt/eslint` stylistic) enforces `commaDangle: 'never'` and `braceStyle: '1tbs'`, plus 2-space indent from `.editorconfig`. This differs from most Prettier defaults — don't add trailing commas. Existing `.vue` files use `<script setup>` before `<template>`.
